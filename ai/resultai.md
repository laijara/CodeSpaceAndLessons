# Конспект: Использование приёмов работы с файловой системой NTFS

## 1. Цель работы
Научиться устанавливать разрешения NTFS для файлов и папок для отдельных пользователей и групп в операционной системе Windows, а также устранять проблемы доступа к ресурсам.

## 2. Теоретические сведения

### Общие сведения об использовании разрешений NTFS
Разрешения NTFS позволяют явно указать, какие пользователи и группы имеют доступ к файлам и папкам, и какие операции с их содержимым разрешено выполнять.
* Применимы только к томам, отформатированным в файловой системе NTFS (не предусмотрены для FAT или FAT32).
* Система безопасности эффективна независимо от того, обращается ли пользователь к файлу локально или по сети.
* Разрешения для папок отличаются от разрешений для файлов.
* Право назначать разрешения имеют: администраторы, владельцы файлов/папок и пользователи с разрешением «Полный доступ».

### Список управления доступом (ACL)
В NTFS для каждого файла и папки хранится список управления доступом (Access Control List - ACL).
* В ACL перечислены пользователи и группы, имеющие права доступа к ресурсу, а также сами назначенные разрешения.
* Для получения доступа в ACL должна присутствовать запись — элемент списка управления доступом (Access Control Entry - ACE) для конкретного пользователя или его группы.
* ACE назначает запрашиваемый тип доступа (например, «Чтение»). Если соответствующей ACE нет, доступ запрещается.

### Множественные разрешения и наследование
* **Множественные разрешения:** Пользователю можно установить несколько разрешений напрямую или через группы, членом которых он является.
* **Эффективные разрешения:** Представляют собой совокупность всех разрешений пользователя. Например, если пользователь имеет право «Чтение» для папки, а его группа — право «Запись», то у данного пользователя будут оба этих права.
* **Установка разрешений NTFS и особых разрешений:** При настройке безопасности следует руководствоваться принципом минимально необходимых привилегий для выполнения рабочих задач.

## 3. Выполнение задания (Практическая часть)

В соответствии с заданием, ниже представлен отчет о выполнении практических шагов по настройке безопасности NTFS.

### Задание 1. Настройка базовых разрешений NTFS для папки
1. Создана новая директория `C:\LabWork3_NTFS` на логическом диске с файловой системой NTFS.
2. Вызвано контекстное меню папки, осуществлен переход в раздел «Свойства» на вкладку «Безопасность».
3. В целях ограничения доступа из списка пользователей удалена системная группа «Все» (Everyone).
4. В список добавлен локальный пользователь «Студент». Ему назначены базовые права: «Чтение и выполнение», «Список содержимого папки», «Чтение». Право «Запись» оставлено неактивным.

### Задание 2. Настройка эффективных разрешений (Множественные разрешения)
1. Создана локальная группа безопасности «Редакторы», в которую включена учетная запись «Студент».
2. В свойствах безопасности папки `C:\LabWork3_NTFS` добавлена группа «Редакторы» с разрешением «Запись» и «Изменение».
3. Проверка эффективных разрешений: при авторизации под учетной записью «Студент» операционная система объединила права (Чтение от самого пользователя + Изменение от группы). В результате пользователь получил возможность создавать и изменять файлы внутри директории.

### Задание 3. Наследование разрешений
1. Внутри папки `C:\LabWork3_NTFS` создана вложенная директория `ProjectFiles`.
2. При просмотре вкладки «Безопасность» для папки `ProjectFiles` было установлено, что она автоматически унаследовала все разрешения от родительской папки (отображаются права для пользователя «Студент» и группы «Редакторы»).
3. Для директории `ProjectFiles` было разорвано наследование (кнопка «Дополнительно» -> снятие отметки «Наследовать разрешения от родительского объекта»). В диалоговом окне выбран параметр «Копировать» для фиксации текущих прав в виде явных разрешений с возможностью их последующей раздельной настройки.

### Задание 4. Устранение проблем доступа к ресурсам
1. Смоделирована ситуация конфликта разрешений: для пользователя «Студент» явно установлено разрешение «Запретить» (Deny) на чтение файла `test_document.txt` внутри рабочей директории.
2. Попытка открыть указанный файл от имени пользователя «Студент» завершилась системной ошибкой «Отказано в доступе».
3. **Анализ инцидента:** В архитектуре NTFS явно заданные запрещающие разрешения имеют наивысший приоритет. Они всегда перекрывают разрешающие правила, даже если те предоставляют полный доступ или получены через членство в привилегированных группах.
4. **Решение проблемы:** От имени Администратора открыты свойства безопасности файла `test_document.txt`, галочка в столбце «Запретить» для пользователя «Студент» была снята. Доступ к документу успешно восстановлен.
